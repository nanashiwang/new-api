## 验证与边界

全量 `go test ./...`、`go build` 通过；对成功限流、验证凭据和模型诊断执行定向 `go test -race`。前端 `node --test scripts/*.test.mjs` 共 20 项通过，`bun run build` 包含图片 Playground 与主站均通过。

三库验证使用独立临时数据库：SQLite、MySQL 8.0、PostgreSQL 16。覆盖迁移重复执行、数据保留、真实约束变更、外键阻止时回滚、JSON、令牌字段迁移、图片预扣和验证凭据 16 路并发只能成功消费一次。未使用生产数据库，也未声称跑过最低支持版本实例。

新版 GORM 扫描结构体会覆盖未选中字段；已将费用和 RPM/TPM 的查询结果独立接收后合并，并由旧统计回归及新增令牌统计回归验证。驱动必须成组升级，Dockerfile 继续保护已验证的四版本组合。

浏览器使用本地 API 模拟数据，不调用生产。检查上游声明差异弹层、订阅金额、真实零值、失败日志、旧日志无新字段、390px 窄屏、暗色和刷新后保持主题。声明名不是实际模型身份的证明，不会触发自动改价/禁用。

## 未纳入与升级风险

- 保留本地 Pulse、钱包付费归因、独立令牌、自动续传、分组健康/首字/缓存统计和 Semi UI。
- 暂不引入新前端、RelayKit/任务插件、WebSocket Responses 体系、vLLM/SGLang 管理和 Ollama 行为开关。
- Passkey 已修直接绕过与挑战/ready 结果重放；没有声称完成上游全部 session/action-scoped proof 与统一登录二次验证架构迁移。
- GitHub 旧用户名绑定必须经其他已绑定方式登录并显式重绑，不再自动按用户名归并账号。
- 新增验证凭据表；上线前备份并排空在途请求。限流新 Redis 命名空间不沿用旧短窗口计数；避免旧新版长期混跑。
- PostgreSQL 历史唯一约束被其他外键依赖时迁移会停止并回滚，需先人工核对依赖，不能强行 CASCADE。
- Responses 已交付内容的失败请求可能产生实际消费账单；错误行本身不作为“零扣费”依据。
- 原生图片 SSE 未提供真实数量时仍保留原有回退口径；本轮实际数量修复针对可识别的 JSON 图片载荷及其转流路径。
