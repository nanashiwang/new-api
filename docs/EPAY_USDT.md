# 通过 Epay 收取 USDT / TRC20

此入口复用现有易支付配置，同时支持余额充值和套餐购买。业务订单按人民币计价，客户在 Epay 收银台使用 USDT / TRC20 付款；Epay / BEpusdt 确认到账并发送签名通知后，new-api 更新订单和权益。

## 配置

1. 在 Epay 商户中心准备好 BEpusdt 网关，完成接口校验、真实到账测试、启用及设为 USDT 默认通道，并确保商户套餐权益有效。
2. 在 new-api 的「系统设置 → 支付设置 → 通用设置」填写可访问的服务器地址，供支付通知使用。
3. 在「易支付设置」填写 **Epay 平台地址、商户 ID 和商户密钥**。已有易支付配置可直接复用。
4. 打开「虚拟币支付 → 启用 USDT / TRC20」，点击「更新支付设置」。刷新后核对开关，再到普通用户的钱包页面确认余额充值和套餐购买均有该方式。

BEpusdt 网关地址、API Token、TRON 钱包及付款窗口在 Epay 商户中心维护，不填入 new-api。钱包私钥和助记词不需要提交给 new-api。开关不会部署网关，也不会代替 Epay 的到账测试。

开关直接管理现有 `PayMethods` 中的如下条目，保留支付宝等其他条目和已有自定义字段；手动编辑 JSON 也会同步开关。默认不会自动添加该方式，已有 `usdt.trc20` 配置会显示为开启。

```json
{
  "name": "USDT / TRC20",
  "type": "usdt.trc20",
  "color": "#26A17B"
}
```

`PayMethods` 完整配置须为对象数组，各字段值均为字符串。关闭并保存后不再接受此方式的新订单，已创建订单的有效到账通知仍会正常处理。

## 金额与验收

- 余额充值继续使用现有人民币报价规则。例如每美元额度价格为 7.3 元且无分组倍率或折扣时，充值 2 美元额度产生 14.60 元订单。套餐继续使用原有套餐订单价格规则。
- 实际 USDT 数量以 Epay 收银台显示为准，不按 `1 USDT = 1 元` 换算，也不由 new-api 承诺 USDT 汇率。
- 付款必须使用 **TRC20** 网络、收银台地址及精确 USDT 数量。此配置不代表支持 USDC、ERC20 或其他网络。
- Epay 通知中的 `money` 必须是原人民币订单金额。new-api 继续验证通知签名及订单金额，并防止重复入账。
- 「钱包管理 → 账单」可按 USDT / TRC20 筛选，支付金额仍为人民币；真实币额和链上交易记录在 Epay / BEpusdt 或钱包核对。

本轮代码使用独立 SQLite、合成账号和本地 Epay 协议桩验证页面下单、签名通知、余额及套餐到账；另有错误签名、错误金额、重复通知、关闭后在途通知和用户记录隔离的自动回归。这不能替代真实链上验收。升级后应从业务站发起一笔小额付款，核对钱包到账、Epay 已支付、new-api 余额或套餐生效三者一致。

无需新增数据库迁移；版本发布不自动启用通道或部署生产。
