# 调用失败日志

用户可在使用日志的“调用失败”筛选中查看自己的失败请求，展开后可复制排查信息。字段包含请求 ID、模型、接口路径、HTTP 状态码、失败状态码、错误码、总耗时、处理建议及可用的 Retry-After。

- 一次请求只按最终结果记录失败。渠道重试最终成功时不新增失败行；最终失败时最近 5 次渠道尝试作为管理员诊断保存。
- HTTP 200 并不代表流式请求成功。响应开始后的显式流内错误仍会记录为调用失败，HTTP 状态与错误状态分开展示。
- 记录已识别用户的鉴权拒绝、限流、渠道分配失败、参数及额度校验失败、上游错误和任务提交接口失败。无法识别用户的无效密钥请求不归入任何用户日志。
- 不读取或复制请求正文，也不缓冲模型响应。用户接口只返回公开的排查字段；渠道信息、上游诊断和尝试详情仅管理员可见。
- 失败行不充当账单，也不凭 usage 缺失推断免费。费用以相同 Request ID 下的消费或退款记录为准。
- 异步任务提交成功后的运行结果继续在任务日志查看；已有消费日志中的流式异常标记继续保留。本功能不将无明确错误的 HTTP 200 或零 usage 自动视为失败。

## 开关与升级

管理设置 → 运营设置 → 日志设置 → “启用调用失败日志记录”。默认开启；未保存面板设置时使用 `ERROR_LOG_ENABLED`（默认 `true`），已有显式 `false` 配置继续有效。

升级不会补造历史失败日志。旧错误日志可能来自单次渠道尝试，无法推断当时整个请求是否最终失败；其内部诊断仅管理员可见。

用户查询接口为 `/api/log/self?type=5`，支持现有时间范围、模型、令牌名称和 `request_id` 筛选，始终按登录用户隔离。错误行沿用既有日志保留和清理策略，不计入消费金额统计。
