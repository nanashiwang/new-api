# 使用日志：厂商与多渠道筛选

管理员使用日志页保留原布局，在原分组位置拆分“厂商 / 分组”，原渠道 ID 位置使用普通文本框，支持名称关键词或多个渠道 ID，顶部增加“分组汇总”弹窗入口。

## 查询示例

1. 设置时间范围，厂商选择 OpenAI，分组不选。
2. 渠道框输入 `muze`；也可输入 `1352,1365`，按明确的渠道 ID 查询。
3. 点击查询查看明细和顶部统计，点击“分组汇总”查看整个时间范围的各分组消费记录数、额度与输入/输出 Token。

查询条件之间为交集。厂商根据每条日志的实际分组名称识别，不根据渠道协议类型，也不根据渠道当前绑定的分组推断。一个渠道绑定多个分组不会导致重复统计。

## 边界与兼容

- 名称关键词由后端解析为匹配的渠道 ID，输入后点查询即可，不再使用下拉选择。无匹配时查不到记录，绝不退回全部渠道。
- 名称使用不区分大小写的包含匹配，SQL 通配符作为普通字符处理。匹配超过 200 条时报错并要求缩小关键词，不静默截断。
- 禁用渠道仍可搜索。渠道已删除时可输入其 ID；历史分组可输入准确名称查询。名称匹配依据当前名称，不提供历史名称快照。
- 明细、统计、榜单、汇总共用同一个厂商/渠道范围。日志库和渠道库可以分开，不做跨库 JOIN。
- 普通用户页面不增加管理员渠道信息；新接口必须经过 AdminAuth。
- 不改渠道、分组、密钥、倍率、路由，不增加数据库字段或迁移。

## 统计口径

- 顶部额度、缓存率以及分组汇总沿用消费记录口径，不把失败重试记录、退款记录混入调用量。汇总列明确称为“消费记录数”，不是所有请求尝试数。
- RPM/TPM 仍表示当前最近 60 秒，且与所选时间范围取交集；不是整段时间的平均每分钟值。
- 缓存率沿用原有逐条 Token 加权计算与 `LOG_CACHE_RATE_SCAN_LIMIT` 抽样限制，不平均各渠道百分比。分组汇总不另计算缓存率。
- 汇总查询覆盖完整时间范围，不受明细分页影响；输出超过 1000 个分组时提示缩小范围，不静默截断。
