# CPA 用户身份转发

在 CPA 渠道的“渠道额外设置”开启“CPA 用户身份转发”，设置实例标识（例如 `newapi-main`）。同一 New API 站点的所有 CPA 渠道使用相同标识；不同站点使用不同标识。此开关默认关闭，仅对可信 CPA 目的地开启。

后端渠道 `setting` JSON 对应字段：

```json
{"cpa_user_identity_enabled": true, "cpa_instance_id": "newapi-main"}
```

转发的专用头为 `X-CPA-Instance-ID` 和 `X-CPA-User-ID`。用户 ID 取自 New API 已鉴权的内部 `RelayInfo.UserId`，不取客户端的请求头、正文 `user`、令牌 ID 或 session ID。不同令牌属于同一用户时，发出的用户身份不变。实例标识为 1–64 位字母/数字/点/下划线/短横线，以字母或数字开头。

覆盖顺序为适配器设置、自定义请求头、最后注入可信身份。未开启的公共转发入口会移除这两个保留头，避免透传客户端伪造值。缺少用户 ID 或实例标识无效时，请求在发送前失败。携带身份的 HTTP 请求禁止跨源或降级重定向；原有代理、超时和同源重定向策略保留。

已覆盖统一 HTTP（包括 SSE）、表单、WebSocket 握手入口，适用于走这些入口的 OpenAI、Claude、Codex 渠道。异步任务统一请求入口同样注入身份，但独立绕过公共入口的适配器不在本次支持范围。渠道测试使用其内部测试用户 ID，不代表真实租户流量，启用 CPA 租约前应单独规划测试用户权限。

New API 只负责可靠传递身份。CPA 仍需实现：把此服务端渠道 Key 绑定到允许的实例；校验用户身份；租约分配与到期释放；跨重试/会话的隔离；剥离身份头后再转发模型上游。不能因收到这两个头就信任任意持 Key 的来源。CPA 渠道 Key 不发给终端用户，生产链路使用 TLS。

本次没有实现或启用一小时租约，没有改变现有用户分组、计费、渠道选择或线上配置，也没有给非 CPA 渠道自动开启此功能。
