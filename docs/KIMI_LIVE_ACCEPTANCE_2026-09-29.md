# K3 真实入口验收结果（2026-09-29）

## 结论

**所测「Kimi · 优质（第三方）」分组尚未满足客户验收要求，不能宣称全部修复或验收通过。**

本轮实际向元衡接口发送了 61 次请求（包含被拒绝的请求），不是本地模拟结果。动态工具、字符串视频输入、Messages/Responses 入口和延迟均出现明确失败。部分基础功能通过，但不能覆盖这些失败项。

- 实际入口：`https://nan.meta-api.vip/v1`，不是客户摘要中的 `new.yuev2.cn`。
- 线上版本：开始及结束核对均为 `main-18a2e98`；本地未提交改动未部署。
- 时间：北京时间 2026-09-29 21:06–21:39；最终状态核对 21:43。
- 使用用户为本轮提供的测试令牌；令牌值不写入本报告、代码或产物。
- 默认分组请求经多个渠道处理，结果属于当时的分组链路，不代表任意单渠道全部通过。
- 官方基线：`MoonshotAI/Kimi-Vendor-Verifier` 提交 `66092cf444c97356c0e11c5078c67116390615d9`，原测试源码和断言未修改。

## 性能补充测试

参数：25 次请求、并发 2；每条输入约 130 token，要求顺序输出 1–150；`reasoning_effort=low`，`max_tokens=2048`，单次最多 55 秒。从本机到元衡公网入口计时，含网络与网关路由耗时。

这是一组满足“小于 8K”输入范围的补充样例，不是客户未提供的原始 `sla_bench` 脚本原样复跑。

| 客户端连接中断 | 2/25 |

| 可测首个有效输出样本 | 24/25；另 1 条没有收到有效输出，不记作 0 秒 |

## 三协议及交付/计费核对

独立 Node 进程执行 4 项，**2 项 Chat 流式通过，Messages 与 Responses 各失败 1 项**。不能把脚本正常退出写成四项业务通过。

- Messages：请求 `20260929133757759503153C7GMFkfD`，路由 `1468 → 1466`，HTTP 404；对应错误日志额度 0。
- Responses：请求 `20260929133758911915977u0VE98LY`，实际 1468，HTTP 500；对应错误日志额度 0。
- 两条独立 Chat 流式均完整返回 1–150；没有在这两条中复现之前的意外断流，不能据此否定之前的观测。

性能测试中两次客户端意外断流，服务端却记录为 `stream_status=ok` 并产生消费：

- `20260929133115425706846XsKwKgeQ`，实际 1468，客户端未收到有效输出。
- `20260929133226405046584vNvzp6vS`，实际 1466，客户端只收到推理片段。

第三条 `20260929133439907982123WBPlvOjr` 是本测试在 55 秒主动取消，不能混同意外断流。上述现象需要分别检查公网连接、客户端与服务端的结束状态；**尚不能认定就是客户所说的“失败正文伪装成功”计费漏洞，也没有直接补偿或修改余额。**

61 次请求中，58 条按响应请求 ID 精确匹配到选列生产日志；对应消费额度合计 4,187,107 个内部 quota 单位。另 3 条响应头 ID 与日志 ID 不一致，未直接加入此精确合计。同令牌时段内还有未归属于本次测试的调用，未计入本次结果或费用；不把整段令牌用量增量当成本次费用。
