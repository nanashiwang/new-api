# Agent Note: 在渠道管理整合期间用量以辅助调整权重

Status: implemented

## Problem

管理员需要比较指定时期的渠道消耗并调整分配权重。累计已用/剩余不能回答期间消耗；另开统计表会让观察和操作继续分离，并与已有看板重复定义指标。

## Decision

渠道管理在同一张表切换配置/用量视图。用量视图显示时段消耗、全范围占比、日志请求数与成功率，保留优先级、权重编辑；配置列偏好、累计已用/余额和周期额度策略保持各自含义。看板保留分组表、汇总和渠道用量跳转，完整渠道列表只在管理页展示。

[监控聚合定义](../../../../model/monitor.go) 的 `channelMonitorAggregates` 由看板和 [渠道用量](../../../../model/channel_usage.go) 共用。新增管理员 `/api/channel/usage` 是渠道配置与统计的组合列表接口，负责主库筛选、全量排序、分页与元数据，不引入独立的统计表或第二套计费算法。日志库可独立部署，两库分别查询，不做跨库 JOIN。

## Query and accounting contract

- `[start_time, end_time)` 精确到秒，最多 30 天，拒绝非法、颠倒、未来及超长区间。今天/昨天按北京时间划分；页面显示时区、实际范围、生成时间和缓存状态。缓存沿用 `CHANNEL_MONITOR_CACHE_TTL`（默认 60 秒），键包含精确时间、模型和日志分组，不为命中缓存移动边界。
- 看板使用 `exact_range=true` 取得同样的半开区间，跳转携带该区间。旧监控调用不传此参数时保留原缓存桶对齐及闭区间行为；两类缓存键隔离。
- 消费日志计成功、错误日志计失败，额度为这两类保留日志中的 `quota` 合计。它不是上游采购成本、所有重试尝试成功率或余额。未记录失败、日志清理与后续调账影响历史完整性。
- 名称/ID/密钥/地址、状态、分类及当前渠道能力过滤复用现有查询。模型、分组还约束实际日志；分类计数不受具体分组选择影响。标签模式沿用现有模式语义，只统计符合筛选的有标签渠道，不应用分类页签。
- 占比分母是全部匹配的可管理渠道，先按时段消耗排序再分页，相同消耗按渠道 ID 稳定排序。标签分页单位是整组，子渠道不拆页；成功率使用累计成功数/累计请求数。无日志为零，零分母占比为 0，无请求成功率为横线。
- 删除渠道的历史消耗在同时间/日志筛选范围单独提示，不受已不存在的渠道配置条件约束，不进入占比分母。没有渠道归属的错误记录不分摊给现存渠道。
- 日志跳转保留渠道 ID、时间、模型和分组；半开结束时间转换为日志页的闭区间结束秒。渠道范围显示在可编辑的渠道筛选框。日志页额度统计仍仅计消费记录，通过提示说明差异，不改变既有日志口径。标签超过日志接口的 200 渠道上限时，展开查看单渠道日志，不静默截断。
- 普通用户无法访问该接口；列表查询排除密钥，沿用管理员渠道信息清理。失败与旧后端缺能力显示错误，绝不补零；可切回配置视图。首版不自动调权。

## Alternatives considered

- **只保留看板统计**：改动最少，但分析和调整权重需要跨页，未满足操作目标。
- **渠道管理另做独立统计表和计费聚合**：组合容易，却需要维护两张渠道表及两套指标；采用同一管理表和共享聚合定义，仅增加必要的组合列表接口。
- **直接搬整个监控面板**：界面复用最多，但分组分析不属于渠道配置，原表缺少筛选、全局排序和权重操作，因此只迁移渠道操作场景。

## Consequences

管理员可在同一行对照消耗调权，查询口径和零值/失败含义明确；没有数据库迁移。代价是聚合成本随选定时段的日志量增长，配置筛选与标签排序在主库返回集合上完成。查询利用既有 created_at 索引，缓存减少同区间分页的重复扫描，但不宣称生产负载收益；若 30 天查询在真实负载下仍慢，需要另行评估预聚合和保留策略，不能以静默截断替代。

看板总量可包含已删除及无归属记录，管理页分母只包含当前筛选可管理渠道；两者不是无条件相等。模型/分组筛选同时受当前渠道配置影响，不提供历史配置快照。页面缓存不是实时余额；权重影响请求分配，不保证金额份额。
